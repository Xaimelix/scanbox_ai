# ScanBox AI — MVP без сборки железа: пошаговая реализация

> **Цель:** за ~2–3 недели получить рабочее демо для стендовой выставки (2-я половина ноября 2026) **без сборки физического прототипа** (без турели, ESP32, камеры, LiDAR).
>
> **Идея демо:** посетитель даёт фото объекта (или выбирает готовое) → система генерирует 3D-модель → модель можно покрутить в браузере прямо на стенде. Это «трогабельное» впечатление без физического железа.

---

## 1. Концепция демо для стенда

| Что | Как |
|---|---|
| Вход | Фото товара (с телефона посетителя или из галереи пресетов) |
| Обработка | Image-to-3D модель на GPU в облаке (Selectel / Cloud.ru) |
| Выход | GLB-модель + вращающийся 3D-просмотр в браузере |
| Показ | Ноутбук на стенде + большой экран; посетитель видит «сканирование» в реальном времени |

**Почему это работает на стенде:**
- физически «пощупать» можно экран и интерактив (покрутить модель мышью/пальцем);
- эффектно выглядит процесс: фото → спиннер → готовая 3D-модель за 30–120 секунд;
- не нужны ни турель, ни камера-риг, ни LiDAR — MVP доказывает core-ценность (фото → 3D-актив).

## 3.5. Автоматизация: эфемерный GPU-сервер как CD-пайплайн

**Идея:** не держать GPU-сервер включённым вообще — поднимать его **на время одной задачи** (создание 3D-модели), а после — удалять. Это тот же принцип, что в CI/CD: раннер собирает билд в эфемерной VM и умирает. Здесь «джоба» = генерация модели: фото → вычисления → GLB → сервер исчез.

**Жизненный цикл одной генерации:**

```
[Фото] → Оркестратор
            ├─ 1. Создать VM с GPU (Selectel / Cloud.ru API)    ← ~1–3 мин
            ├─ 2. Настроить (cloud-init / Ansible / golden-image)
            ├─ 3. Запустить генерацию (Hunyuan3D-2.1 / stable-fast-3d)
            ├─ 4. Забрать GLB → S3-хранилище / Drive / локально
            └─ 5. Удалить сервер (всегда, даже при ошибке)      ← экономия
```

**Что это даёт:**
- платишь только за минуты реальных вычислений (RTX 4090 у Selectel ≈ 250–350 ₽/ч, т.е. ~4–6 ₽/мин реальной работы);
- ноль простоя: сервер живёт ровно столько, сколько идёт генерация;
- параллельность: 2–3 запроса = 2–3 эфемерных сервера (или очередь на одном);
- чистота: каждый запуск — свежая система, никакого мусора между джобами.

**Инструменты:**
- **Terraform / OpenTofu** — декларативное создание и удаление VM (провайдеры Selectel и Cloud.ru есть);
- **Ansible или cloud-init** — настройка окружения (CUDA, PyTorch, зависимости);
- **Packer** — «золотой образ» с уже установленным Hunyuan3D-2.1: настраиваешь один раз, дальше сервер готов за 1–2 мин;
- **Оркестратор (свой FastAPI-сервис)** — принимает фото, дёргает API провайдера, ведёт статусы `provisioning → ready → generating → uploading → done → deleting`, отдаёт GLB;
- fallback-провайдер: не отдал GPU Selectel → пробуем Cloud.ru через тот же интерфейс.

**Минимальный скелет оркестратора:**

```python
# orchestrator.py (упрощённо)
def run_generation(photo_url: str) -> str:
    server = provider.create_server(flavor="rtx4090", image="scanbox-golden")  # 1
    try:
        server.wait_ready(timeout=300)                                       # 2
        glb = server.run("python generate.py --input photo.jpg")             # 3
        url = storage.upload(glb)                                            # 4
        return url
    finally:
        provider.delete_server(server.id)  # 5 — выполнится ВСЕГДА, даже при ошибке
```

**Тайминги:** поднятие сервера 1–3 мин (5–10 мин до первого запуска, пока нет golden-image), генерация 30–120 сек, удаление ~10–30 сек. Для стенда: либо предзапуск сервера утром, либо «живой» подъём под посетителем (эффектно, но нужен запас ~5 мин — можно показывать прогресс «поднимаем GPU 🚀»).

**Риски и митигации:**

| Риск | Митигация |
|---|---|
| Холодный старт (первая генерация медленная) | Golden-image (Packer) + держать 1 «тёплый» сервер в часы стенда |
| Лимиты API провайдера (квоты на GPU, rate limits) | Проверить заранее, fallback-провайдер, запас по квоте |
| Падение во время джобы | `finally` гарантирует удаление; результат потерян → просто перезапуск |
| Тарификация (час/минута) | Удаление сразу после джобы = платим только за использованное |

**Итог:** сервер — не ресурс, а **функция**: `фото → GPU на 5 минут → GLB`. Это и есть «CD для вычислений»: тот же конвейер, что собирает и убивает CI-раннеры, только вместо билда приложения — модель.

## 4. Архитектура MVP (без железа)

```
[Посетитель] → Фото (телефон/галерея)
      ↓
[Веб-интерфейс: FastAPI + HTML/JS]  ← на облачном сервере
      ↓ загрузка фото
[Обработчик задач] → [Hunyuan3D-2.1 / stable-fast-3d] (GPU)
      ↓
[GLB-файл] → [Three.js viewer в браузере]
      ↓
[QR-код на стенде] → посетитель открывает модель у себя на телефоне
```

Все компоненты живут на **одном GPU-сервере** (Selectel RTX 4090): и веб-морда, и инференс. Никакого железа локально не нужно.

## 5. Пошаговые шаги реализации

### Шаг 1. Аренда сервера (Selectel) — 30 минут
1. Регистрация на selectel.ru, создание проекта.
2. «Облачные серверы» → создать сервер с GPU:
   - конфигурация: 1 × RTX 4090 (24 ГБ), 8 vCPU, 32–64 ГБ RAM, диск 200–500 ГБ NVMe;
   - ОС: Ubuntu 22.04/24.04;
   - включить внешний IP (для доступа с ноутбука на стенде).
3. Подключиться по SSH: `ssh root@<IP>`.
4. Погасить сервер после теста — оплата почасовая.

### Шаг 2. Базовая настройка сервера — 20 минут
```bash
apt update && apt upgrade -y
apt install -y python3-pip python3-venv git ffmpeg libgl1 libglib2.0-0 curl
# CUDA-драйвер (если не предустановлен)
nvidia-smi   # проверить, что GPU виден
```

### Шаг 3. Установка Hunyuan3D-2.1 — 1–2 часа (один раз)
```bash
git clone https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1.git
cd Hunyuan3D-2.1
python3 -m venv venv && source venv/bin/activate
pip install torch==2.5.1 torchvision==0.20.1 torchaudio==2.5.1 \
    --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
# компиляция rasterizer (могут быть нюансы — смотреть README)
cd hy3dpaint/custom_rasterizer && pip install -e . && cd ../..
cd hy3dpaint/DifferentiableRenderer && bash compile_mesh_painter.sh && cd ../..
# веса Real-ESRGAN для апскейла текстур
wget https://github.com/xinntao/Real-ESRGAN/releases/download/v0.1.0/RealESRGAN_x4plus.pth -P hy3dpaint/ckpt
```

**Быстрый тест (Gradio UI):**
```bash
python3 gradio_app.py \
  --model_path tencent/Hunyuan3D-2.1 \
  --subfolder hunyuan3d-dit-v2-1 \
  --texgen_model_path tencent/Hunyuan3D-2.1 \
  --low_vram_mode
```
Открыть `http://<IP>:8080` — уже можно загружать фото и получать GLB.

> Если Hunyuan ставится тяжело — fallback: **stable-fast-3d** (`pip install stable-fast-3d`, запуск через `sf3d` CLI), ставится за 15 минут.

### Шаг 4. Веб-сервис поверх модели (FastAPI) — 2–3 дня
Структура:
```
scanbox-demo/
├── app.py              # FastAPI: upload → job → status → download GLB
├── worker.py           # очередь задач, вызов Hunyuan3D/stable-fast-3d
├── static/
│   ├── index.html      # страница: загрузка фото + спиннер + viewer
│   └── viewer.js       # Three.js: загрузка GLB, орбита, свет
├── presets/            # 5–10 готовых фото для мгновенной демо
└── outputs/            # сгенерированные GLB
```

Ключевые endpoints:
- `POST /api/upload` — принимает фото, создаёт job, возвращает `job_id`;
- `GET /api/status/{job_id}` — статус (`queued → processing → done`);
- `GET /api/result/{job_id}` — готовый GLB;
- `GET /` — страница демо.

Очередь: проще всего `queue.Queue` в одном процессе (1 GPU = 1 задача за раз), на стенде этого достаточно. Для красоты — прогресс-бар «сканирование: 23%».

### Шаг 5. Фронтенд для стенда — 2–3 дня
- **index.html:** крупная кнопка «Загрузить фото», drag-and-drop, галерея пресетов (коробка, кроссовок, кружка — сгенерировать заранее);
- **Three.js viewer** (CDN `three@0.160+` + `GLTFLoader` + `OrbitControls`):
  - автовращение модели (турнтейбл-эффект — как раз то самое «покрутить коробку»);
  - перетаскивание мышью, зум колесом;
  - тач-управление для телефона;
  - фон-градиент + мягкий свет (HDRI-подобная среда);
- **QR-код** на стенде: ссылка на `/view/{job_id}` — посетитель открывает модель на своём телефоне (мобильный AR позже, в MVP — просто 3D-просмотр);
- брендинг: логотип ScanBox AI, подпись «Фото → 3D за 60 секунд».

### Шаг 6. Пресеты и «мгновенная демо» — 1 день
Сгенерировать заранее 5–10 GLB из готовых фото (коробки, товары):
- это страховка на случай, если посетитель не захочет ждать генерацию;
- выглядит как «мы уже всё отсканировали, вот результаты».

### Шаг 7. Репетиция стенда — 1 день
- Проверить на реальном ноутбуке + проекторе/ТВ (контраст, крупный шрифт);
- замерить тайминг: фото → GLB (цель < 2 мин на Hunyuan, < 30 сек на stable-fast-3d);
- подготовить сценарий рассказа: 30-секундный питч + ответы на вопросы («как это работает?», «сколько стоит?», «где используется?»);
- **бэкап-план:** если интернет/облако подведёт — открыть локальную копию index.html с заранее сгенерированными GLB (офлайн-демо всегда работает).
